I moved the REPL's line-input buffer off the stack and onto the heap: it was a 2 MiB array declared as a local in repl(), which crashed the Windows cross-build with a stack overflow the instant the REPL started, before it printed anything. Linux's much larger default thread stack had been silently absorbing this the whole time.

Found by actually running the Windows build under Wine rather than trusting a clean cross-compile. Confirmed by re-running it after the fix: the REPL now boots fully, prints the whole boot sequence, and shuts down cleanly on quit, with no crash. The buffer's size and behavior are unchanged; only where it lives changed. Full suite still at 262 passed, 0 failed.
